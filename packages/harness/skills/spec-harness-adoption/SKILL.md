# 读取、适配并接管流程

由[Bootstrap](../../bootstrap/BOOTSTRAP.md)启动。先读取[权限与协作](../../rules/collaboration.md)，涉及委派/隔离/能力路由再读[委派规则](../../rules/delegation.md)。客户端执行本包程序，不读取源码来重编译；稳定流程含义、禁止项、权限、Gate、状态、异常与验收预期不能被本地适配改变。

## 1. 固定来源，接管基线

从用户提供的发行入口或既有绑定解析固定版本，既有绑定优先，不默认升级最新。检查 manifest.json 的版本、source_revision、清单、引用完整性及兼容约束；按[身份说明](../../README.md)核验可信发行与外置通过证据，Hash 本身不是可信或验证证明。缺正式包/通过依据则 BLOCKED，不能把源码、占位说明或候选当正式发行。

唯一候选例外见[受控候选测试](references/candidate-validation.md)：必须先有包外维护者授权，且只替换正式发行/通过证明前置，其余检查不放宽。

调用[项目接入](../spec-project-onboarding/SKILL.md)，建立/复用 Adoption Baseline 与 01A/01B/Resume。再读[全局执行](../../rules/global.md)、[完整路由](../../bootstrap/routes.md)、当前 Skill 及依赖与[能力要求](../../bootstrap/requirements.md)。保留未激活流程的入口与要求，不能把未加载当作不适用。到这里仅证明包、基线和路由确定，不证明本地 Harness 生效。

## 2. 沿需求发现当前环境

先发现 Agent/Host/Runtime 身份、实际版本、加载位置/作用域/生效条件、已有 Instructions/Skills/Hooks/工具及所有权，再查项目已有构建/测试/CI/Git/状态/证据和当前流程所需隔离、权限、模型、并发。真实缺口才查扩展来源。

用当前元数据、本地配置、可执行探测；缺口再补版本匹配官方资料。unknown 不等于 unavailable，Reference 不证明能力已可用。每个当前必需能力要有实现证据或明确缺口；关键未知未关闭不能假定可用。先查事实，不预选配置文件/插件，不枚举全市场或重做业务认知。动态证据放运行记录，不进稳定 Adoption Baseline。

## 3. 选择、装配与固定本地候选

先用满足完整要求的已有机制，再考虑组合；实际缺口才获取/创建额外能力。顺序为：守语义及权限；需要可靠检查/阻断的优先确定性机制；采用有实际收益的原生能力；保持渐进加载、等价可靠时优先可移植/既有机制；降低重复、权限、上下文、运行维护成本。可选增强不是 Workflow 默认前置。缺原生可等价替代，必要行为仍不能满足则阻断依赖流程；提示词不能代替明确要求的隔离或强制门禁。

保留未修改原包；在授权的目标范围写环境配置/派生资产。让全局约束和路由进入实际加载面，明确重载/新会话条件。保留用户资产，按来源、作用域、权限处理冲突，不用覆盖文件隐式解决。安装/连接/写入复用已有授权，确需额外权限时先形成可审阅方案。检查组合后的共享依赖、异常、阶段转换。

在已有工作空间记录：包身份、实际范围、管理的文件/配置、复用机制、要求→实现、环境证据、失效条件；标明转换/组合资产的原包来源和影响依赖。用文件 Hash/配置快照及 Runtime 身份固定本地候选，Runtime 名称/版本不能代替内容身份。不建大型 Schema。后续流程保持可达，其能力激活前再验收。

## 4. 验证与接管

对转换、提取、拆分、组合或 Runtime 映射的资产，直接对照未修改原包的完整相关行为与共享依赖，回查步骤、Gate、Authority、状态、异常、Guidance，不能只对能力名或适配者摘要。原样复用且依赖/作用域不变可引用 Hash 和既有有效语义证据，但仍验证当前加载与行为。验收预期固定在原包版本、资产和出处；可改方法/参数，不可随适配结果改预期。风险需要独立 Reviewer 时，其直接读原包和本地候选。

随后确定性检查身份/路径/作用域，实际确认 Runtime 加载了规则与入口、工具可用，逐项证明当前能力要求。文件存在不是加载证据。运行正常推进、权限/Gate、异常路由、必要恢复及共享/按需加载场景；不能只靠格式检查证明行为。行为 Agent 只消费已部署且路由可达的候选、目标项目和场景；不借未路由的原包行为或 Canonical 补缺。语义评审与行为执行分工，独立性看实际上下文边界。

本地验收只证明适配保持包行为，不代替维护者全量审查，也不代替阶段06业务验证。

| 失败 | 回到 |
|---|---|
| 包缺失/矛盾/发行身份无效 | 维护者构建发布或重新获取可信包 |
| 稳定意图/绑定无效 | 项目接入 |
| 环境事实错误/能力变化 | 环境发现 |
| 实现映射/组合/本地配置错误 | 适配装配 |
| 验证方法不能证明要求 | 修正方法并重验 |

候选修改使受影响证据失效，重新固定身份并重验行为和共享影响，不能沿用旧通过。记录 READY/BLOCKED、原包与本地身份、范围、证据和限制。READY 只覆盖明确 Runtime/项目/执行范围，未激活未验证能力不宣称就绪。正式接入无阻塞后自动进入已定 Workflow；候选测试只执行授权场景。新阶段/异常能力未验收时，先补适配与验证，再做依赖动作。

## 5. 复用与运行中恢复

再次进入先检查记录有效性，不重复安装/全量生成。包、Runtime、加载配置、项目机制、用户修改、激活范围的相关变化只刷新受影响链路，范围不明就扩大检查。执行中 Model/Tool/隔离/Fallback 改变，也必须在受影响动作前复核并按需返回发现/适配/验收，不等下次接入，不重编译规范。

接入记录不是永久环境真相。管理资产被用户改动时先查差异、所有权和语义，不直接覆盖。升级前保存恢复原配置依据，失败只回退本次管理变更、保护用户资产。退包版本也要核对当前项目兼容性，旧 READY 不代替当前检查。
