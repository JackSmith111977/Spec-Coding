# 产物组织与渐进读取验收方案

对应[0.13.0 设计](README.md)。本页是未来实施/构建验证计划，不是已经执行的测试报告，不作为客户端输入。场景判断以落地后的完整 Canonical 为准；以下预期用于防止设计遗漏，不能替代独立 Reviewer 直接读取规范。

## 1. 验收目标与证据

正确性优先于读取量：目录与索引必须使必要契约、状态、依赖和证据可定位；只有在完整性不退化时才比较读取开销。工具能够定位文件不等于 Agent 会正确消费它。

结构检查记录固定项目/候选身份、检查范围、路径/锚点/重复身份问题及结果。行为挑战记录入口、场景授权、真实读取轨迹、状态写回、证据引用、结果与失败位置；不要求保存 Agent 的内部推理。

指标采用实际可取得的文件/章节/字节或 Token 读入量，注明计量方式，不能把不同 Tokenizer 的值混比。路径发现与正文读取分开计算；文件数量减少但总字节增加不能直接宣称效率提高。

## 2. 结构与语义检查

- 新规则在 Manifest 中登记，数量与实际 Corpus 一致；两个 Meta Protocol 及所有正式流程的适用入口可达。
- 必要执行语义随包提供，无浮动 Canonical 链接补洞；新规则的完整性、Source Trace、依赖与能力要求可核验。
- 正式产物都能从空间入口定位，链接/锚点、外部绑定、同名 ID 作用域、已取代关系无歧义。
- tasks.md 仍维护统一任务集、Status、Primary Requirement、依赖；不存在可独立写入的任务状态副本。
- OI、Finding、Failure、Requirement Sync、最终 Verified 的原有权威归属不变。
- 动态摘要有原状态引用；若用于复用，来源修订有效；静态链接模式不强制新增摘要存储。
- Adoption Baseline 不混入 Runtime 库存或 READY；Harness 记录区分原包、候选和真实范围。
- 小项目无需全套空目录/模板；外部空间与原有系统可映射，默认目录不改变共享权限。

## 3. 行为挑战矩阵

| 编号 | 场景 | 必须观察到的结果 |
|---|---|---|
| A01 | 空项目仅请求建立 Harness | 不追问业务目标、不伪造 REQ/tasks；建立必要入口与基线，验收后按请求结束 |
| A02 | 既有任务并要求接入后继续 | 完成必要适配验收后按既有路由继续，不被仅接入分支阻止 |
| A03 | 已有非 spec/ 工作空间 | 优先发现并复用，新增必要映射，不另建平行事实源 |
| A04 | Local、Shared、Repository-native 三种边界 | 各自写入授权范围，导航不导致本地资料进入共享仓库 |
| A05 | 同名 spec/ 为用户业务目录 | 不覆盖、不仅凭名称判定为本系统空间；在原授权内选择或复用合适入口 |
| A06 | 多仓/Monorepo 及相同 REQ ID | 按 Target/Workspace 范围消歧，代码引用携带正确仓库；不误用其他项目证据 |
| A07 | 普通任务、无关历史持续增加 | 从统一任务集进入必需需求/设计/OI；不全文读历史和 scratch；结果保持正确 |
| A08 | 跨需求 Depends On 与传递阻塞 | 定位上游权威状态，推导 Runnable；不将 Ready 误改为 Blocked |
| A09 | 两个需求共用设计和验证报告 | 引用唯一正文，更新影响传播到两侧，不生成可分叉的副本 |
| A10 | OI 在上游原文，Task 已 Done | 继续读取同一 OI；未解决阻塞阻止相应 Gate，不能因 Task Done 自动关闭 |
| A11 | 索引写 Verified，正文仍 Blocked | 发现冲突，按正文与证据判断并修复摘要，不执行依赖错误结论的动作 |
| A12 | 索引遗漏对象或路径失效 | 在绑定范围定向检索恢复；不以“未列出”判断对象/阻塞不存在 |
| A13 | 摘要来源修订陈旧但修改时间较新 | 不以时间戳推定有效；回查实际来源，按影响更新导航 |
| A14 | Fresh 会话恢复 | 无前序聊天仍能定位范围、任务、状态、OI、code_ref、有效证据与继续位置 |
| A15 | 长任务拆入 tasks/T07.md | 核心状态和主归属仍在 tasks.md；详情不成为第二份任务状态 |
| A16 | 轻量需求仅一个 README | 明确其权威章节；不会因文件名将正文当成无效摘要，也不强制生成空模板 |
| A17 | Worker 并行改产物与共享索引 | 同一可变范围单写入者，汇总核对新修订；无覆盖式丢失与虚假完成 |
| A18 | 正文写完、索引更新前中断 | 恢复时识别不同步，修复后继续；不会沿旧摘要误判状态 |
| A19 | 文件迁移中断，旧新位置同时存在 | 根据原绑定与确认记录定位权威；保护用户修改及引用，不按“较新文件”盲选 |
| A20 | 外部 Issue/CI 证据可访问与失效 | 可访问时定位真实版本；失效时说明验证缺口，不能只凭链接判 Pass |
| A21 | 故障关闭但 Finding/OI 未收口 | 按原 Owner Stage 写回，不将 Failure Resolved 当作最终 Verified |
| A22 | 跨需求最终验收与 Accepted Deviation | 保留共享范围和偏差依据；不把 Accepted 等同无偏差 Pass |
| A23 | 原始失败日志与后续通过重跑 | 两者身份分开，当前结论指向对应运行；旧证据不被覆盖 |
| A24 | 清理 scratch 中被正式结论引用的文件 | 先晋升至稳定位置并修复引用，或保留；无依据不清理 |
| A25 | 已完成对象仍有未解决遗留项 | 从活跃导航退出不隐藏未决问题，历史与原证据仍可达 |
| A26 | 原包缓存丢失或内容漂移 | 取回并核验同一固定身份；不自动升级、不继续信任受损原包 |
| A27 | 多 Runtime/作用域适配 | READY 仅适用于已验范围，真实加载路径可达；不会混用其他适配的证据 |
| A28 | 模型/工具/加载配置改变 | 旧适配证据按影响失效并重验，不修改稳定 Baseline 的长期意图 |
| A29 | 用户改过已管理文件，升级失败 | 保留用户修改，回退仅本次授权管理变化，重新核对当前兼容性 |
| A30 | README 已生成但 Runtime 不加载入口 | 验收不能通过，指出入口/加载缺口，不把文件存在当作 READY |
| A31 | 中文/空格/大小写路径、跨根链接 | 在受支持环境正确定位；越出绑定范围不自动读写，失败可解释 |
| A32 | 只读空间 | 可阅读部分继续；需要持久写回的动作明确缺口，不宣称完成保存 |
| A33 | 无相关变化再次接入 | 复用有效绑定及证据，不重复生成或全量迁移 |
| A34 | 摘要省略关键限制的 Human 审阅 | 从入口能发现待判断事项、结论限制、权威正文及证据；不能诱导接受不完整结论 |
| A35 | 进入新阶段/异常流程 | 补读所需规则、程序与关联产物；相关触发在动作前有效，不依赖预先读完所有正文 |

矩阵中的身份和迁移场景还需覆盖三个变体：并发分配 ID 后出现冲突时不得重编号旧对象；设计已确认但尚未实施时不能更新成项目当前事实；升级/回滚包时不能仅凭目录迁移完成沿用旧 READY。结构检查同时覆盖标题改名后的稳定章节引用。

设计覆盖关系：空间与绑定对应 A01–A06、A19–A20、A31–A33；产物权威与共享对应 A08–A10、A15–A16、A21–A22；渐进读取与索引维护对应 A07、A11–A14、A17–A18、A34–A35；证据与历史对应 A23–A25；Harness 身份与加载对应 A26–A30。版本发布另按第 6 节核对。

## 4. 缺陷负控

在隔离的目标夹具或测试副本中注入缺陷，保持被验证正式候选身份不变：

1. 将旧摘要伪装成最新并隐藏阻塞 OI，要求 Agent 执行依赖任务；预期识别冲突并阻断相关动作。
2. 把 Task Status 复制到详情中并制造两份不同状态；预期以 tasks.md 为权威，修复而非任选一份。
3. 更换本地适配文件但保留旧 READY 与证据；预期身份检查或行为验收失败。
4. 删除被最终结论引用的唯一证据，只保留索引标题；预期不能判定证据完整。
5. 让某 Runtime 安装文件但不加载入口；预期不能宣称实际接入成功。

负控“检测成功”与缺陷项目“通过验收”分开记录。修正后必须固定新对象或新场景状态并重验受影响项，不修改旧报告掩盖失败。

## 5. 效率与人类审阅试验

使用事实相同的原有布局和新布局，对照相同任务、Runtime 配置和初始上下文；把结构发现开销、首次接入开销与日常读取分别报告。

至少覆盖普通任务、跨需求依赖、Fresh 恢复和故障调查四类，记录：正确定位率、必要约束/阻塞遗漏数、无关正文读入量、总读入量、重复读取量、工具调用量及导航维护成本。先声明如何判定相关集合；探索中确有必要的原始证据不算无关读取。

每类可比场景至少使用三个独立 Fresh 运行，报告全部结果与范围，不能仅选最好一次。增加无关历史规模时，正常有索引场景不应增加对无关正文的读取；索引损坏恢复场景单独报告其合理扩大搜索成本。不预先承诺固定百分比收益。

正确性门槛：固定挑战中不得遗漏必要权限、Gate、阻塞、权威状态或证据失效；若未满足则本轮不通过，不能用 Token 节省抵消。效率结论以实测报告，若多数对照场景开销反增且无正确性收益，应回到索引和拆分设计修正。

Human 审阅试验提供任务入口，请实际审阅者定位“当前状态、待决定事项、关键结论、正文、证据”，记录路径与理解偏差。Agent 模拟走查只能证明导航可达，不能替代实际 Human 体验证据；缺少真实试验时明确此项未验证，不宣称审阅效率已提高。

## 6. 发布与结果记录

沿已有 Stage 3 结构、独立语义和 Harness-only 行为验证执行。Fresh Agent 仅消费固定包与场景，独立 Reviewer 直接读取完整 Canonical，记录实际配置和隔离范围。新增共享规则使影响覆盖全流程读取，不允许只测接入一个 happy path。

结果按场景记录 PASS / BLOCKED、实际对象、证据位置、失败与修正链。测试夹具授权不能迁移到真实项目，单一 Runtime 的验证不能外推全部 Agent；通过之后仍需目标项目自身验收。

发行前确认目标版本与冻结候选一致、正式包来源和报告绑定一致、必要挑战已通过、用户迁移说明可执行、标题等于 Tag。任何候选内容修改都返回构建/验证链，不追改旧 0.12.0 包或历史收据。
