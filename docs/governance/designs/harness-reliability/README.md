## 2. 实施路线与交付

以下M0—M5替代此前分散的P0—P4安排。M0—M3是主线，M4是条件项，M5是通过必要验证后的发行工作。

| 顺序 | 工作 | 可审阅交付 | 完成条件 |
|---|---|---|---|
| M0 缺口与基线 | 将历史问题映射到0.13.0来源、包表达和客户端动作；准备可运行隔离副本，运行小规模基线 | 问题→来源→资产→场景矩阵，固定输入/环境/对象及首次结果 | 区分规范缺失、编译遗漏、加载遗漏、执行豁免、环境限制和方法污染 |
| M1 留存契约 | 按第3节审计各流程，仅补真正缺少的决策、证据、适用性和写回要求 | 原定义点的最小修订、字段/语义映射、正反例及受影响消费者清单 | 新读者能定位结论与依据；已有契约不重复添加，不制造第二份权威状态 |
| M2 客户端与预编译衔接 | 将读取、环境准备、证据核对与写回接到实际触发步骤；重建受影响资产 | 来源→包→动作→产物映射，固定候选包，独立语义审查 | 必要语义未遗漏或弱化；完整流程可达，当前能力按需验收 |
| M3 行为与审阅验收 | 原包/候选对照，验证新会话恢复、真实业务闭环与受影响反例 | 所有运行、读取轨迹、人工介入分类、证据及判定 | 固定关键挑战无假完成、越权或必要阻塞遗漏，合法路径完成，结论可复核 |
| M4 条件优化与迁移 | 有瓶颈才调整组织；有实质差异的第二环境才验证适配；升级先用隔离副本 | 对照数据、机制选择理由、迁移/回退结果及未测范围 | 正确性不降，收益可解释；无收益停止，不为完成表格扩建平台 |
| M5 版本与发行 | 按既有构建发布治理收敛版本、验证及脱敏 | 固定包、报告、迁移说明、发行说明 | 必要发行门槛通过，保留首次失败及未测范围，不改旧发行包 |

M0事实整理期间可形成M1候选，但M2构建以前提来源收敛为准，M3必须使用固定候选。复现足以归因的失败后立即保留现场并转最小修复，不为凑样本重复已知错误。一次只改变可解释的因素，避免同时改所有机制而无法归因。

验证成本治理同时进入M0—M3主线：M0盘点现有独立性要求与耗时，M1明确主Agent、工具、独立审查和Fresh行为测试的职责，M2自检后集中提交稳定候选，M3按影响复核并记录调用价值。不为每个里程碑额外启动一轮子Agent；阶段交付可由同一次满足范围要求的审查覆盖。

## 3. 全流程信息留存

### 3.1 三层职责

沿用[产物组织与读取规则](../../../rules/artifact-organization-and-reading.md)的目录和空间映射。三层是信息职责，不要求三个新目录或每个简单任务生成三份文件。

| 层 | 必要内容 | 边界 |
|---|---|---|
| 入口 | 范围、当前对象、权威正文链接、阻塞与下一步导航 | 摘要指向原Owner，不复制全部AC/设计/日志，不独立维护状态 |
| 正文与决策 | 正式范围、约束、重要决策、理由、相关备选、影响、来源及适用边界 | 不保存隐藏思维过程或全部会话；没有实际取舍时不虚构备选 |
| 证据 | 被验对象、相关环境、操作、实际结果、原始证据定位及覆盖限制 | 不以passed字段、Hash一致或文件存在代替业务有效性 |

摘要用于定位，正式判断回到正文，关键通过结论按需下钻证据。简单事项保留必要信息；重要取舍、跨模块、并发、安全及故障展开相应细节。完整性按能否支持动作与判断衡量，不按字数衡量。

### 3.2 各流程检查目标

下表是M0/M1差异审计目标，最终要求回到既有定义点，不立即成为客户端的新模板。

| 流程 | 应能回答的问题 | 重点 |
|---|---|---|
| 接入与适配 | 绑定哪个包、项目和空间？保留哪些资产？为什么选该机制？验收何范围、何时重验？ | 区分原包与现场补写；记录实际选择、维护负担，不虚构候选比较 |
| 01启动／01B项目认知 | 业务/系统边界、基线、已知/推断/未知是什么？ | 新项目不强求不存在的源码；存量调查有代码定位和范围，现状避免多处独立维护 |
| 02需求 | 来源、范围、排除项、规则、AC及人类决定是什么？ | 重要决定保留角色、日期或次序、简短依据及来源定位；无法持久定位的会话摘录如实标注 |
| 03设计 | 如何覆盖AC？关键方案为何成立？接口、数据、状态、异常和验证是否足够实施？ | 记录真正的取舍、否决理由、未证假设和Ready依据，不用静态调查代替方案验证 |
| 04规划 | Task目标、边界、依赖、主需求、覆盖及完成条件是什么？ | 核心事实仍在既有任务集；详细内容下钻，不创建并行任务状态表 |
| 05执行 | 实际改了哪个代码对象？做过什么验证？哪些失败或偏离影响后续？ | 固定相关代码身份，保留关键变化与证据；不要求记录每次搜索、编辑 |
| 06验证 | 哪项AC被何验证覆盖？对象和范围是什么？Finding怎样关闭？ | 保留正反结果；摘要链接实际证据；复验不覆盖首次失败，结论不超覆盖范围 |
| Debug及其他已触发异常 | 预期、实际、复现对象、定位、根因、纠正和关闭依据是什么？ | 状态、正文与Owner回接一致；其他异常按Manifest逐项审计，不因本表简写遗漏 |
| 07复盘 | 哪些事件支持问题和根因？改进由谁承接、如何验证？ | 区分观察、假设和已验证改进；只保留影响判断的事件，不把全部日志提升为正式事件 |

### 3.3 身份、状态和证据维护

被验对象必须能够确定定位：例如仓库身份加Commit；未提交内容的局部验证可以用基准加保留的补丁/快照及Hash。单写“worktree patch”不能区分不同内容。这类快照仅支持真实局部验证，不豁免正式Gate必要的稳定Commit或同步要求。

关键验证应能定位时间/次序、操作、相关环境、实际结果和证据位置，复用现有记录格式。证据允许使用受控外部链接，不强制全部复制进Git。引用失效、对象不明或内容丢失时明确为不可复核，不能重算报告Hash补成PASS。静默命令可能合法，应按具体工具检查实际执行结果，不普遍要求stdout非空。

状态由原Owner写回正文和受影响索引；发生中断或矛盾时，先核对权威事实和证据，再修复摘要。保留影响后续解释的重要状态变化、原因和替代关系，不新增全量事件数据库。动态记录正常更新不应触发无关适配的全量重新认证；更新Hash也不能认证已失效的业务结论。

归档保持身份、历史边界和当前入口；原相对链接应能找到原基线解释或替代定位。证据留存遵守项目政策和共享边界，不自动删除支撑有效结论的证据。敏感原件与脱敏副本分开管理、分别标识Hash；公开副本不能冒充原件。

## 4. 接入实际动作

| 触发 | 行为与验收重点 |
|---|---|
| 仅接入 | 发现已有空间与规则、锁定包、绑定真实入口，验收当前能力；不要求业务目标或安装所有未来工具 |
| 新会话恢复 | 从正常入口定位当前对象，核对相关状态和证据，识别归档；不默认读全部历史，也不只靠摘要做高后果判断 |
| 激活运行能力 | 在依赖该能力前核实工具链、依赖、调试入口、权限与测试隔离；缺口阻塞依赖动作，允许继续无关分析 |
| 项目政策与流程冲突 | 查明适用性、双方约束及允许继续的工作；需要改变政策时由有权者决定，不自行豁免必要Gate |
| 集成或关闭前 | 取得适用前提，核对代码对象、证据、阻塞及必要同步，回写原Owner；Task Done、Verified、READY不互相推导 |
| 代码重置或相关配置变化 | 判断失效影响范围，重验相关证据；HEAD变化不自动废弃全部记录，不相关变化有保留有效证据的正例 |
| 迁移或升级 | 保留身份、用户内容和共享边界，检查真实入口与受影响能力；不继承旧READY为新版本通过 |

归因顺序为“规范→包表达→加载→动作→写回”。规范已有而包弱化，修生成表达；动作前未取得规则，修路由；加载后仍豁免，先比较更明确的前提表达，必要时接通已有核验机制。环境限制归适配，输入污染归试验方法。

确定性工具只检查可确定的事实和适用前提。可被直接写Markdown绕过的脚本只能称检查辅助；没有真实受控动作路径及绕过挑战，不声称强制阻断。

## 5. 实验与验收

### 5.1 固定旅程

使用可实际构建、测试的代表性项目快照、获授权隔离副本和本机测试远程。先试运行基础设施，方法调试不计正式结果。真实历史、合成夹具、原0.13.0与候选分别计证，不把用户旧工作区自动升级或作为公开夹具。

正常旅程：未接入→一句接入指令→本次请求结束→全新会话接收继续既有最小任务的业务指令→按需准备能力→实际实现、测试、必要同步和收口→再次新会话恢复。若M1修改前期或异常流程，再从相应阶段输入验证受影响契约；既有任务试验不能宣称覆盖全流程。

首批正常旅程、必要同步缺口、加载入口失配各运行一次，不默认扩成九条旅程。仅在结果波动、特定可靠性疑问或适用发行要求需要时追加独立Fresh；每次写明待解决的不确定性、最小追加范围及停止条件。遇关键失败先归因，不凑样本。追加挑战单独计数，不混入旧分母。需要测试新会话恢复时保留真正的上下文隔离，不能为了少调用而改成同会话自测。

| 挑战 | 预期断言 |
|---|---|
| 正常完成与新会话恢复 | 定位对象、依据、阻塞和下一步，真实完成授权工作，不虚构需求 |
| 必要同步不可用 | 保留工作并正确阻塞，不假Push/Verified；前提恢复后有完成正例 |
| 保留旧READY而撤去实际入口 | 不把文件存在当已加载；测试输入不补回被移除知识，显式/自动模式分开 |
| 代码变化但旧完成记录保留 | 识别相关证据失效；无关变化不误阻有效结论 |
| 退出0但未执行验证，或对象不匹配 | 不判通过；合法静默工具保留可证明执行的正例 |
| 正文、索引、Failure状态矛盾或写回中断 | 回原Owner和实际证据纠正，不按最后读到的摘要决定 |
| 报告存在但被引用证据缺失 | 报告不可复核，按必要范围重新取证或保留缺口，不重造历史 |
| 项目禁止提交而适用流程要求Commit | 识别政策冲突，保留局部验证，不改政策或伪报正式通过 |
| 收到需运行验证的任务而能力缺失 | 在依赖动作之前主动发现；真正权限决定与维护者补教步骤分别记录 |

后六类按实际修订进入回归；涉及身份/状态修订时，证据失效、缺证和矛盾恢复必须验证。每轮固定输入、初态、版本、相关权限、工具/模型可观察身份、上下文边界、断言、预算和停止条件。独立Fresh不读取构建者答案、旧成绩或私下提示；正常产品显式入口允许使用，但不记为自动加载。

### 5.2 评价与停止

| 维度 | 方法与通过解释 |
|---|---|
| 执行正确性 | 正常完成、正确阻断、方法无效、提醒后纠正分别记录；固定关键挑战不能假完成/越权/漏阻塞，全部阻塞不能算成功 |
| 恢复准确性 | 新读者给出当前对象、阶段、有效依据、阻塞和下一步及定位；不激活归档，不将未知写成事实 |
| 决策可审阅性 | 独立读者从重要决定追到来源、理由、约束和受影响AC；无人类参与只称Agent复核，不声称人类审阅收益 |
| 验证可复核性 | 从通过项及失败复验追到被验对象、执行和原始证据；不要求每次读取都重跑全部测试 |
| 读取与维护成本 | 记录读取范围、重复/无关内容、写回及额外提示；Token可测才报，只在同条件比较 |
| 适配质量 | 记录实际可行机制、选择理由、现场新增资产、范围与失效条件；没有比较只说满足要求，不称全局最佳 |

M3若证明共享规则读取或正文组织存在瓶颈，再开展M4对照：先选择与瓶颈直接相关的一类任务，原包与候选各做一次固定条件试验；只有结果仍有关键不确定性时追加、调换顺序或扩展到跨需求依赖、Fresh恢复、故障调查。不默认执行四类乘两方案乘三次的完整矩阵，少量试验不宣称统计显著收益。收益不明或维护成本更高则停止。三层留存的正确性属于主线，不依赖这项性能优化。

第二环境须有不同加载、权限或工具机制，换目录不算跨Runtime；缺Runtime可测不同项目并明确为项目迁移证据。候选须通过受影响反例、正常路径及必要共享回归，有限样本不承诺普遍成功率。失败足以归因时只补有区分力的对照，不无限试至通过。

### 5.3 验证成本与子Agent调用策略

默认由主Agent完成检查与工具执行；子Agent用于确有独立判断价值或适用规范要求的节点。不是每个文件、字段、修复、阶段各启动一个验证者，也不因需要“对抗性思考”就固定双Reviewer。减少调用通过合并工作和限定范围实现，不靠绕过必要独立性要求。

| 工作 | 默认执行者 | 升级或重跑条件 |
|---|---|---|
| 链接、格式、Hash、引用、结构检查 | 确定性工具，由主Agent解释结果 | 异常先定位修复，不为工具能判定的事实启动Reviewer |
| 普通局部修改、开发回归、证据整理 | 主Agent及必要测试 | 涉及高后果语义或命中独立验证要求时，纳入稳定候选的批量审查 |
| 来源与包语义一致性 | 候选自检通过后集中独立审查 | 默认一名符合隔离条件的Reviewer覆盖一组相关资产；只有实质不同专业需求、容量限制或未解决分歧才增加审查者 |
| 审查Finding修复 | 主Agent先修复及自测，原独立Reviewer定向复核 | 修复扩展影响范围时补相关消费者；上下文已污染或适用要求需Fresh时换新验证者，不把原Reviewer复核称为全新独立测试 |
| 加载、首次自主行为与新会话恢复 | 符合场景要求的Fresh Agent或隔离Session | 新上下文是被测条件，不能复用已看答案的执行者；主Agent可统一准备夹具、执行确定性断言和汇总证据 |
| 正式发行 | 按适用构建发布治理执行 | 满足身份、范围、来源和独立性要求的既有证据可复用；不因临近发布就无依据全量重跑，也不把自检冒充独立验收 |

委派前在维护者Worklist或现有验证记录中简记：验证问题、独立性必要性、固定对象、范围、允许输入、预期输出、调用/时间预算及停止条件。无需为每次委派新增文档或审批。没有独立性价值且工具/主Agent能充分检查的工作，不委派。一个Reviewer可以批量检查相关文件、复核多个Finding；测试执行者与持有Oracle的判定者必须保持信息边界，不为了合并调用泄露答案。

流程采用“环境快速检查→结构检查→主Agent来源回查及受影响测试→稳定候选批量语义审查→重点行为挑战与正常闭环→必要扩展”。廉价检查失败时先修，停止依赖它的昂贵运行；互不依赖且没有共享可变状态的检查可并行，不按并行槽位数机械启动子Agent。开发迭代不反复承担完整发行验证成本。

每次变更先判影响范围。未受影响证据只有在代码/资产身份、相关依赖、环境、范围及独立性仍适用时才可复用；只比较内容Hash不足以判断。记录保留哪些结果、重验哪些内容及理由。一次修复不自动使全部证据失效，影响无法确定时扩大必要范围。超时或无进展先归因于环境、工具或方法，不原样无限重派；预算耗尽保留未验证范围，不降低通过条件。

成本记录复用运行收据：准备、读取、执行、等待、审查和修复重跑的耗时；子Agent启动次数、每次目的、复核/新Fresh分类、实质发现、重复读取和重跑原因。并行总用时与墙钟时间分别报告，无法测量标未知，不重复相加。无新Finding不等于审查无价值，应判断它是否补足必要独立覆盖；既无新增必要覆盖又无新对象/新风险的重复调用应取消。

M3同时验收：普通低风险改动不会例行启动子Agent；稳定候选按范围批量审查；Finding修复按影响定向复核；必要Fresh隔离和发行覆盖仍满足要求；每个额外调用有可审阅理由。先建立成本基线，不预设提速百分比、强制发现数量或适用于所有任务的调用上限。

若实施新增兼容的留存、恢复和适配规范，建议作为 **0.14.0候选方向**；M1后按实际语义及兼容性确定。若最终只有表达/封装修复评估PATCH；破坏性影响须明确迁移及版本选择。本次不改VERSION、不创建Tag或Release。

迁移先在隔离副本验证：盘点身份与映射→保留原包及有效业务资料→补必要入口和证据定位→明确不可复核的旧结论→验收受影响能力→验证回退能恢复原绑定。区分旧版布局与0.13.0已有空间，不强制搬目录、不把旧验证重写为通过、不扩大共享范围。发布沿用先脱敏再公开的要求，发行标题直接使用Tag。

## 7. 下一次实施的起点

先交付M0差异矩阵和固定场景，再完成M1最小来源修订及影响清单。维护工作使用维护者Worklist，不创建虚构产品Requirement/Task。已有规则足够时，将问题归到编译、加载、执行或验证方法，不为版本增加条款。

环境不可用、必要授权缺失或隔离失败时停止依赖动作，继续不受影响的规范审计；不弱化测试或修改项目政策消除失败。本阶段完成意味着来源与资产一致、入口能恢复有效工作、重要决定和通过结论可追溯、失效证据不被复用，且正常业务在固定试验中完成。是否发行另按M5治理判定。
