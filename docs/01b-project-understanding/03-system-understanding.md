# 3. System Understanding｜系统理解

## 3.1 目标

在 Business Context 基础上，将已确认的业务模型与场景映射到真实系统，明确**业务能力由哪些系统组件承载、组件如何协作、关键场景如何穿过系统、数据与状态如何变化，以及现有系统存在哪些重要约束**。

系统理解聚焦 **As-Is（现状）系统模型**，目标是理解系统如何支撑当前业务，而不是提前设计新的技术方案，也不要求穷尽相关模块的全部实现细节。

---

## 3.2 定位系统范围

从 Project Overview 和 Business Context 出发，将业务范围进一步映射到需要理解的系统区域。

```text
Business Capability
  ↓
System / Service
  ↓
Module
```

确认核心范围、直接依赖与外围依赖，只负责确定理解边界，为后续定向追踪控制搜索空间。

---

## 3.3 建立系统要素认知

### 1. 系统组件与职责

识别相关前端、后端、数据库、缓存、消息队列、任务、文件存储、外部服务等关键组件，并明确一句话职责、边界及协作关系。

### 2. 接口与交互边界

明确 HTTP、RPC、MQ、任务、数据库等交互方式，标识关键同步 / 异步边界与调用方向，不维护完整 API 清单。

### 3. 数据归属与系统约束

将核心业务对象映射到主要系统表示和数据归属，明确关键数据由谁创建、修改、存储和消费，并记录历史兼容、共享消费者、唯一写入方等会影响后续判断的重要不变量。

### 4. 图表规范

系统组件图以系统、服务、模块和数据存储为主要粒度，表达核心组件、职责、依赖、外部系统、关键存储和必要交互方式，不展开 Controller、Service 方法、DTO 或数据库字段。

---

## 3.4 还原系统运行链路

```text
Business Scenario
      ↓
System Entry
      ↓
Control Flow
      ↓
Data / State Change
      ↓
Sync / Async Boundary
      ↓
System Result
```

每条核心链路重点追踪：系统入口、控制流、数据流、状态变化、同步 / 异步边界、关键分支 / 失败以及最终结果。

系统理解通常追踪到“**组件 / 模块 → 关键入口 → 关键 Symbol**”即可；需要证明具体结论时，再通过 Evidence 回到源码、配置、日志或数据，不在 System Context 中复制完整实现细节或私有调用链。

复杂链路按需使用 Sequence Diagram、Data Flow 或 State Machine。

---

## 3.5 验证并固化系统认知

### 验证原则

- 优先验证会影响后续需求定位和技术设计的高影响结论。
- 对同步 / 异步、状态更新位置、数据归属、唯一写入方、共享消费者等关键判断进行证据确认。
- 区分已确认事实、合理推断和仍无法确认的信息。
- 无法确认的重要信息保留为开放项。

### 结构化产物

| 章节 | 内容 |
|---|---|
| `System Scope` | 核心系统、直接依赖、外围依赖及理解边界。 |
| `System Model` | 组件、职责、关系、接口边界、数据归属、关键系统约束及按需系统组件图。 |
| `System Flows` | 核心场景对应的控制流、数据流、状态实现、同步 / 异步边界、关键分支及按需时序图 / 数据流图。 |

重要未确认信息和 Evidence 应附着在对应模型或链路中，避免重复维护独立说明。

### 图表固化原则

- **文本保存精确语义，图表表达结构与运行关系。**
- 按认知问题选图，不机械生成全部图表。
- 使用 Mermaid、PlantUML 等可版本化文本 DSL。
- 同一事实只保留一个规范表达位置。

---

## 3.6 完成标准

新的 Human 或 Agent 仅依赖 System Context，应能回答当前业务由哪些系统承载、关键组件职责、核心业务场景如何穿过系统、关键数据与状态如何流转、重要同步 / 异步边界与系统约束在哪里。

---

## 3.7 下游使用约定

```text
Project Overview
  ↓
Business Context
  ↓
System Context
  ↓
Requirement Locate
  ↓
Requirement Clarification
```

因此，System Understanding 的最终职责是：

> **以最小充分的系统模型和运行链路，使 Human 与 Agent 对“当前业务由哪些系统承载、系统如何协作、数据与状态如何流转”形成一致、可验证、可复用的共享认知。**
