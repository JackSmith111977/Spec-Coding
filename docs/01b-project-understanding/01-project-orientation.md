# 1. Project Orientation｜项目导览

## 1.1 目标

以“广而浅”的方式快速建立存量项目的全局地图，明确**项目是什么、由哪些部分组成、代码在哪里、后续深入探索应从哪里进入**，为后续业务理解、系统理解和需求定位提供稳定的导航基础。

项目导览只负责建立**地图和入口**，不在本阶段深入具体业务规则、完整调用链、数据模型或需求影响分析。

---

## 1.2 识别项目身份

首先确认“这是一个什么项目”，建立后续认知的第一层语义锚点。

### 1. 需要确认的信息

- 项目名称。
- 项目定位与核心职责。
- 主要用户或使用角色。
- 主要解决的问题。
- 仓库类型，例如单仓、Monorepo、多仓协作。
- 技术形态，例如 Web 应用、服务端系统、桌面端、CLI、微服务体系。

### 2. 信息来源与验证

| 优先级 | 信息来源 | 用途 |
|---|---|---|
| 1 | 项目文档 | README、设计文档、Wiki 等。信息密度高，但可能过时。 |
| 2 | 仓库结构 | 确认项目边界、模块划分和代码组织方式。 |
| 3 | Manifest / Build Config | 如 `package.json`、`pom.xml`、`build.gradle`，确认技术栈和工程形态。 |
| 4 | 应用入口 / 路由 | 确认实际运行入口、主要页面或服务边界。 |
| 5 | 代码信息 | 在前述信息不足或存在冲突时进一步验证。 |

---

## 1.3 建立顶层地图

### 1. 业务地图

识别项目覆盖的核心业务领域或能力，明确一句话职责与大致边界，只建立业务目录，不深入具体流程和规则。

### 2. 系统地图

识别前端、后端、数据库、中间件、独立服务、外部系统与第三方依赖，梳理顶层依赖与交互关系，不深入具体调用链。

### 3. 仓库地图

识别相关代码仓库及其职责，梳理顶层目录、核心模块和代码组织方式，明确仓库、模块与业务 / 系统的对应关系。避免复制完整目录树。

---

## 1.4 定位导航锚点

### 1. 梳理模块结构

- 定位关键业务模块及其代码位置。
- 定位前端应用入口、路由入口和主要页面目录。
- 定位后端应用入口、核心模块入口和主要服务边界。
- 定位数据库迁移、Schema 或数据访问层入口。
- 定位中间件、异步任务、外部服务等关键集成入口。
- 定位项目文档、测试、配置和脚本等常用辅助入口。

### 2. 形成导航锚点

优先采用“**概念 / 模块 + 一句话职责 + 入口位置**”表达。

| 模块 / 概念 | 职责 | 导航入口 |
|---|---|---|
| `Contract` | 合同生命周期与预审相关能力 | `backend/modules/contract/` |
| `Frontend Routes` | 前端页面导航与模块入口 | `web/src/router/` |
| `DB Migrations` | 数据库结构演进入口 | `db/migrations/` |

---

## 1.5 项目导览产物

### 归纳原则

- 保留高导航价值、高复用、相对稳定的信息。
- 以地图、职责和入口为主，不重复仓库原始实现细节。
- 避免枚举 API、DTO、数据表、类和完整目录树。
- 对无法确认或存在冲突的信息显式保留。
- 关键结论应能够回到原始仓库或文档验证。

### 结构化产物

| 章节 | 内容 |
|---|---|
| `Identity` | 项目定位、主要用户、核心问题、仓库类型与技术形态。 |
| `Domain Map` | 核心业务领域及其一句话职责。 |
| `System Map` | 前端、后端、数据库、中间件、服务及其顶层关系。 |
| `Repository Map` | 相关仓库、核心目录及其职责映射。 |
| `Navigation Anchors` | 关键模块、入口、路径和后续探索起点。 |
| `Open / Conflicting Information` | 当前无法确认或存在冲突的信息；无则省略。 |

---

## 1.6 完成标准

项目导览不以“把项目全部读懂”为完成标准。新的 Human 或 Agent 仅依赖 Project Overview，应能回答项目定位、核心业务领域、系统顶层组成、仓库组织方式以及继续研究某模块从哪里进入。

---

## 1.7 下游使用约定

```text
Project Orientation
  ↓
Business Understanding
  ↓
System Understanding
  ↓
Requirement Locate
```

因此，Project Orientation 的最终职责是：

> **以低成本、可验证的方式建立项目全局地图和导航入口，使 Human 与 Agent 能够在不重复扫描整个项目的前提下，快速进入后续更深层的业务与系统认知。**
