# 2. Business Understanding｜业务理解

## 2.1 目标

围绕本次需求建立对相关业务的共享认知，明确**需求发生在哪个业务范围、有哪些关键参与者与业务对象、现有业务场景如何运转**，为后续系统理解和需求澄清提供稳定的业务语义基础。

业务理解聚焦 **As-Is（现状）业务模型**，只回答“当前业务是什么、如何运转”，不在本阶段讨论技术实现，也不将需求中的目标行为提前合并为现状事实。

---

## 2.2 定位业务范围

从 Project Overview 和本次需求出发，将探索范围从项目级逐步收敛到与需求直接相关的业务域和业务能力。

```text
项目
  ↓
业务域
  ↓
核心业务能力
  ↓
直接关联业务能力
```

重点确认业务域、涉及能力、能力依赖 / 前后置 / 协作关系，以及哪些直接相关、哪些只作背景、哪些暂不深入。

本步骤只负责确定业务理解边界，不提前展开完整业务流程。

---

## 2.3 建立业务要素认知

### 1. 参与者与业务能力

识别主要参与者，明确业务目标、职责以及可执行 / 不可执行 / 条件受限的关键行为；只描述业务权限，不分析具体鉴权实现。

### 2. 核心业务对象与关系

识别理解当前业务所必需的核心对象，明确包含、归属、依赖、产生等关系，只保留影响业务理解的重要属性，不展开数据库字段或技术实体。

### 3. 核心术语

识别容易混淆、具有特定业务含义或代码 / 产品表述不一致的术语，给出简洁统一定义并明确近义概念边界。

### 4. 图表规范

| 图表 | 适用场景 | 必须表达的信息 |
|---|---|---|
| Use Case Diagram｜用例图 | 多角色、职责或权限边界需要快速对齐 | 参与者、关键业务行为及其关系 |
| Domain Model｜业务领域对象图 | 核心对象较多且关系影响理解 | 核心对象、业务关系、必要关系语义与基数 |

图中只表达业务语义，不应出现 Controller、Service、DTO、数据表、API、技术状态码等实现概念。

---

## 2.4 还原业务场景

```text
Actor / Trigger
      ↓
Business Action
      ↓
Object / State Change
      ↓
Next Action / Business Result
```

每个核心场景至少明确触发者、业务动作、对象变化、状态变化和后续动作 / 结果。

业务规则、权限限制、前置条件和异常路径围绕具体场景表达，只保留会改变业务路径、状态或结果的重要信息。

活动图是核心业务场景的默认视图；只有状态生命周期本身复杂时才按需增加 State Machine Diagram。原则上一个活动图只描述一个核心业务场景，一个状态图只描述一个核心业务对象。

---

## 2.5 验证并固化业务认知

将业务认知与实际系统、业务文档、验收规则、测试、代码行为等证据交叉验证，并通过 Human-Agent 共同校正关键业务语义。

### 验证原则

- 优先验证影响后续需求判断的关键业务事实。
- 明确区分已确认事实、合理推断和仍无法确认的信息。
- 当前代码行为只能作为业务事实的证据之一，不默认等同于正确业务规则。
- 无法确认的重要信息应保留为开放项。

### 结构化产物

| 章节 | 内容 |
|---|---|
| `Business Scope` | 本次覆盖的业务域、核心业务能力、关联能力与边界。 |
| `Business Model` | 参与者、目标与业务权限，核心业务对象、关系、术语，以及按需生成的用例图 / 领域对象图。 |
| `Business Scenarios` | 核心业务场景、对象与状态变化、关键规则 / 分支 / 异常，以及按需生成的活动图 / 状态图。 |

重要未确认信息和证据入口附着在对应章节中，避免额外复制一套重复信息。

### 图表固化原则

- **文本是规范语义，图表是结构化视图。**
- 按认知问题选图，不机械生成全部图表。
- 图表优先采用 Mermaid、PlantUML 等可版本化文本 DSL。
- 同一事实只保留一个规范表达位置。

---

## 2.6 完成标准

新的 Human 或 Agent 仅依赖 Business Context，应能回答业务范围、参与者目标和职责、核心对象关系、核心业务场景、状态变化与关键规则 / 异常。

---

## 2.7 下游使用约定

Business Context 是存量项目认知阶段的业务语义基线，后续 System Understanding 和 Requirement Positioning 应直接复用，不重复重建业务模型。

> **以最小充分且经过验证的 As-Is 业务模型，使 Human 与 Agent 对当前业务语义与核心运行方式形成一致、可复用的共享认知。**
