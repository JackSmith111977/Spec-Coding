## 治理适用性

1. §3.4 要求 Fresh/隔离行为执行者不读 Canonical，并覆盖 normal、boundary、authority/gate、exception/routing 等代表性场景；入口或消费契约变化时，必须从未安装起点实际执行 Bootstrap、Onboarding、环境发现、适配及验收。
2. §3.5 允许按影响增量验证，不要求全系统、全 Runtime 或固定重复次数；共享规则、Bootstrap、Routing 或组合变化仍须包级集成挑战。证据复用需要原对象与未受影响依据，不能转移旧包整体 PASS。
3. §3.6 只有结构、独立语义、必要行为、最终身份和 validation_focus 同时满足才可 PASS。将已通过的决策题限制写清楚，并不能免除尚未覆盖的必要真实消费验收。

scope 明确 `package_integration_required: true`，四份变更来源同时影响 delegation、05、06、harness-adoption，以及 entry/routes/requirements 和其他共享消费者。本轮不是仅版本外壳刷新：已有语义审查确认 Bootstrap 加入批量复核与 Fresh/复用要求，Project Onboarding 增加条件加载 delegation，candidate-validation 支持资源也改变了实际消费指引，因此 §3.4 的入口/消费契约变化条款适用。

## 剩余真正阻断项

### R1：入口及共享消费变化的真实适配/包级验收覆盖不足

依据：治理 §3.4 第409行、§3.5 第432–433行、§3.6 第474及476行。

目前 A 证明了局部工具执行，B/C/D 证明了情境判断。原记录也确有会话读取与接入准备，不能抹去这些真实动作。但它明确未验证实际首次恢复、委派隔离机制、持久自动加载等；仅把文件列为“已读”、创建导航和给出正确安排，尚不能证明本轮修改后受影响的消费入口与必要隔离/恢复要求能够在真实边界下成立。

不要求所有这些能力都实现：若采用基础文件读取作为合法加载方式，可用该方式验收，不强制安装插件或持久 Hook。当前需要补的是所选方式从真实入口完成必要接管、读取权威状态、加载相关共享规则及守住动作边界的可观察证据；没有必要先完成产品业务或实际多 Agent 复核。

### R2：必要真实消费挑战的隔离证据不足

依据：§3.4 第388–396行及 §3.5 第439行。behavior-verdict 的“未见污染”仍保持原含义，不升级成“证明没有污染”。没有完整日志不是推定执行者违规，但当前材料不能独立核验必须满足的输入隔离和真实加载边界。

最小处理是从原执行系统导出已发生实验的启动输入、相关读取/工具调用和纠正消息，而不是要求重跑所有 A/B/C/D；可脱敏，但须保留候选身份、来源类别、先后顺序及原始结果。若这些材料已足以补齐 R1，可直接交本 Reviewer 定向复核；若不够，则只对下面新增的一次集成挑战留下这些证据。无需记录不可取得的模型内部推理。

## 最小补充挑战（仅定义，本轮不执行）

可合并为一条有两个真实上下文阶段的短挑战，不制造四个新 Reviewer，也不重复 B/C/D 问答。

**场景与权限：** 使用同一固定 frozen-r1，包外明确授权一个隔离测试项目、可写记录/配置范围、禁止修改候选/全局配置/发布及停止条件。准备最小既有权威状态：一个可验证的局部对象、一项尚未满足的依赖或 Gate、与之相连的状态/证据入口；它们是合成夹具，不需要真实产品实现。不给执行者 Oracle、旧成绩或 Canonical。

**第一阶段——真实接入验收：** 无已安装 Harness 或既有适配的执行上下文，从固定 Bootstrap 实际完成 Onboarding、必要环境发现和所选加载映射，保存明确身份/作用域/要求到机制的证据，并执行一个小型约定检查。允许基础文件读取作为加载实现；无需为了“适配”强行创建插件。现有初次接入若能通过原始记录证明相同要求已完成，可以复用相应部分，不机械重做。

**第二阶段——真实隔离恢复与组合边界：** 在未见前序聊天及 Oracle 的新隔离上下文，只给固定真实入口、测试目标和授权，从持久项目入口自主找到权威对象、未满足依赖/Gate及必要证据。实际按包内路径加载所需流程和 delegation；要求一个依赖尚未满足的后续动作，观察其保留合法局部结果、停止受阻动作、记录原 Owner 的承接点，不伪造 Done/整体 PASS。若要测试异常路由，只需让一个入口索引陈旧或产生可可靠观察的局部失败，记录其按需回读/路由恢复，不能靠场景直接告诉应读哪条规则或预先给答案。

**最小通过证据：** 两阶段的实际启动输入与上下文边界、候选及项目对象身份、读取路径和工具输出、真实产生的必要状态/证据记录、所有中途提醒与失败，以及最后限定范围结论。确认行为执行者没有依赖 Canonical/Oracle；若接受了关键语义补救提醒，保留该失败并单独说明纠正后结果，不能叫首次自主通过。由本 Reviewer 按 Oracle 定向判读；本 Reviewer 不兼任盲测执行者。

这条挑战解决真实接入/恢复和共享边界组合缺口，不要求完整 Task→Requirement→Release 闭环，不要求实际提交代码或再制造局部 Finding。若只能证明会话内知情重读，则相应恢复项仍未通过；不能以缩窄措辞豁免当前适用的必要验收。
