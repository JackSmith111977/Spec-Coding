# 验证方法纠正

这些记录解释试验设施变化，不改变Canonical、冻结候选或业务正确性标准。

1. Windows PowerShell Transcript不能可靠捕获部分Git原生stdout/stderr。保留原始转录，后续采用subprocess显式捕获两条流及退出码。S03协调者在解除提交故障前实际复核钩子拒绝、确认HEAD未变，并另存`.coordinator/admin-commit-recheck.json`，明确其为设施复核而非Worker原始操作。
2. S08-B设计的函数已经遍历所有命令，但覆盖A夹具文件时意外省略CLI入口，会引入本不属于B的接口故障。在任何行为Agent读取B之前，为场景定义补回相同JSON命令入口，保持B的全部执行及失败汇总逻辑。旧`s08-b-r2`仅完成物化，未执行，弃用；新`s08-b-r2-v2`从修正资料初始化。不得把此夹具修复算为候选包修复或通过证据。
3. 无实际复杂setup的物化脚本原先可能生成看似可投递的目录。工具现对S03/S06/S07合成或故障分支默认拒绝，显式manual标记只得到PENDING_MANUAL_SETUP；实际设施建立并保留证据后才改READY_FOR_EXECUTION。该状态不表示任何Harness或业务已READY。

4. S04-A独立Verifier第一次读取权威tasks.md时同时看到了Worker写入的结果摘要（IV-CTX-01）。之后独立执行精确代码提交的测试、边界和CLI检查，未读取Worker完整推理。保留这项上下文污染限制，不能表述为完全盲审。
5. S06-A采用实验分段输入，先仅接入，写真实项目加载入口；协调者随后物理撤回管理员验证设施，新会话从项目入口接管。观察实际探测失败后恢复相同字节，再继续。分段暂停不是永久业务门禁；业务Gate仍使用项目指定的真实精确提交验证设施，不能由协调者口头恢复代替实测。
6. S06-B负控删除本地包9个行为文件中与OI及阻断相关的25行，同行的其他语义同时丢失；完整性清单重算，结构自洽。它不是只改变一条规则的单变量实验。行为通道与独立原包P/本地L语义通道隔离；后者直接全量比对并发现8项阻塞。行为中的实测探测和场景输入存在解释空间，不把个别状态推进归因为唯一变异。缺陷L不修复、不晋升，本轮检查的是本地转换门禁能否发现丢失。
7. S07-A的0.12.1与新source_revision来自隔离Git源仓库中的真实版本变更，仅用于新旧包选择试验，不是实际发行。夹具没有提供既有业务Task，因此只验证旧绑定优先和资产保护，未声称完成旧任务业务续跑。
8. S08-A的新机制执行器尚未进入最初业务code_ref。独立Gate明确固定业务提交与执行器原始字节Hash的组合，后续集成再纳入机制变化；不把旧提交中的旧执行器冒充已验证版本。
9. 原始证据归档保留每个执行者实际消费的包，包括故障对照。额外自动测试验证故障正文逐字节保留及归档期间证据变化时拒绝输出通过；归档自身没有语义PASS权限。
10. CLI S06-A初次恢复虽有正式Gate与推送证据，却未以原ID承接第二段的OI-S06A-P2-001和FAIL-S06A-P2-01，第三段写“阻塞OI：无”缺少收口依据。独立评审将该案例阻断；不能把业务通过改写成当时状态收敛已正确。初次20案例归档（SHA256=28a91e498523b24b760985284f8ff1b11fdd3eb0afba31013fc654256ec000a9）保留不变，后续以具体Finding返回同能力配置的Fresh CLI Owner，允许追加原ID追溯和项目当前权威入口，并复用未变化对象的有效测试证据。追加动作使用新记录及独立归档，最终判定须再经Oracle复核；这不是未经提醒的一次成功恢复证明。
